# DART 기업분석실 — 구현 명세

기준일 2026-11-07 (한국 시간). 선택한 모든 연간·중간 기간에 같은 XBRL 문맥 검증 경로를 적용합니다. 검증 표본과 후속 범위는 같은 폴더의 `NEXT_SESSION.ko.md`에 있습니다.

## 사용자 흐름

회사 검색 → 연결/별도·조회 연수 선택 → 최종 공시 수집 → 계정 매핑 및 원천 보존 → 결정적 계산 → 계정별 과거 비교·재무제표 간 대조 → 공시 근거 확인 → 보고서 저장.

첫 화면은 네 가지 가상 시나리오를 제공하며 실제 기업 분석과 명확히 구분합니다. 기본 상세 기간은 최신 연간입니다. 중간 실적은 상세 기간을 바꿔 확인합니다.

## 실행 구조

- Python 3.11+, Streamlit 화면, Plotly 차트, httpx 수집, openpyxl 보고서.
- `app.py`가 `dart_analyst/ui.py`를 실행합니다. `ui.css`는 화면 스타일, `presentation.py`는 금액·상태·표의 표시만 담당하며 계산 엔진과 분리됩니다.
- 별도 데이터베이스 없이 세션에 자료를 보관합니다. JSON으로 저장·재분석할 수 있습니다.
- 기본 바인딩은 127.0.0.1:8501입니다. 인터넷 공개·로그인·다중 사용자 운영은 구현 범위 밖입니다.
- `requirements-tested.txt`는 통합 검증에 사용한 직접 의존성 버전입니다.
- Windows 원클릭 진입점은 `DART_Analyst_Start.cmd` → `run_windows.ps1`입니다. 설치된 Python으로 `.venv`를 만들고 의존성·로컬 Ollama·모델을 확인한 뒤 앱을 시작합니다. `-CheckOnly`는 경로 및 가상환경만 점검합니다. `app.py`와 CLI는 `.env`를 읽습니다. 설정 키는 `DART_API_KEY`, `OLLAMA_BASE_URL`, `OLLAMA_MODEL`이며 예시는 `.env.example`에 있습니다. 로컬 기본값은 `http://127.0.0.1:11434`, `qwen3.5:4b`입니다.
- `DART_Analyst_Start.cmd`는 ASCII 유지가 필요합니다. PowerShell 스크립트는 Windows PowerShell 5.1에서 한국어를 읽을 수 있도록 UTF-8 BOM을 유지합니다. 의존성 import 실패는 첫 설치 분기의 정상 신호이므로 오류 출력 때문에 런처가 먼저 중단되지 않도록 합니다.

## 데이터 모델

| 객체 | 주요 필드 |
| --- | --- |
| Dataset | company, corp_code, stock_code, scope, source_mode, periods, notes, issues, metadata |
| Period | label, year, start, end, scope, kind, filing_id, facts, comparatives, raw_accounts, issues |
| Fact | key, name, amount, unit, currency, statement, start, end, period_kind, scope, attribution, account_id, source_id, source_url, source_field, reason |

금액과 단위는 Decimal입니다. `None`과 0은 다릅니다. BS는 시점, IS/CIS/CF/SCE는 흐름 기간을 구분합니다. FY와 YTD를 구분하고 원문 필드·접수번호를 유지합니다.

`facts`는 표준화한 당기 계정, `comparatives`는 현재 공시에 기재된 비교 계정, `raw_accounts`는 미매핑 계정도 포함한 원천 전체 행입니다. 가져온 JSON은 형식·유한 금액·단위·날짜·중복 기간을 검사하고, 앱에서 출처를 `import`로 표시합니다.

## 수집 계약

```python
with DartClient(api_key) as client:
    companies = client.search_companies(query)
    dataset = client.load_company(
        corp_code, name, stock_code='', years=5,
        scope='CFS', include_interim=True,
    )
```

앱에서 사용하는 API는 `corpCode.xml`, `company.json`, `list.json`, `fnlttSinglAcntAll.json`, `fnlttXbrl.xml`, `document.xml`입니다.

기업개황에서 결산월과 업종 코드를 확인합니다. 업종 코드는 지표 적용 여부에 사용합니다. 사업·분기 공시를 기간별로 묶고 최종 접수번호를 고릅니다. 전체계정 API가 반환한 접수번호가 선택한 공시와 다르면 해당 기간을 보류합니다. 연결 자료가 없다고 별도 자료로 대체하지 않습니다.

전업종의 12월 정규 결산 원화 자료를 지원합니다. 업종 코드가 `64`, `65`, `66`으로 시작하면 공시 비교와 회계 대조는 수행하고, 유동비율·순이익 현금 전환·이자보상배율·순차입금·FCF·DSO·DIO·현금흐름식 발생액은 적용을 보류합니다. `64992` 지주회사도 같은 지표 보호 기준을 적용합니다. 은행·보험 전용 감독 지표는 별도 지원 범위입니다. 전체계정 API에는 실제 duration 문맥이 없으므로 정규 연간 기간을 가정했다는 이슈를 남깁니다. 단기 사업연도·결산기 변경은 지원하지 않습니다. 중간 IS/CIS는 `*_add_amount` 누적 필드를 사용하며, CF/SCE의 누적 기간이 확인되지 않으면 보류합니다.

## 매핑과 전체 계정 비교

표준 XBRL ID와 검토된 정확한 한국어 계정명을 사용합니다. 후보 복수·ID와 계정명 충돌·자본 구성원 불명은 자동 선택하지 않습니다. 차입금과 총부채, 이자비용과 금융비용, 현금 지급 배당과 자본 인식 배당을 구분합니다.

전체 원천 계정의 비교 키는 `재무제표 + account_id + account_detail`입니다. 행 순서나 이름 유사도로 계정을 연결하지 않습니다. 승인되지 않은 회사 확장 코드, 계정 누락·중복·구성원 변경은 상태와 사유를 남깁니다. 부모·자식 계정을 임의로 합산하지 않습니다.

현재 공시의 비교열을 우선 사용합니다. 비교열이 명시적으로 빈칸·오류이면 과거 공시로 대체하지 않습니다. 비교열 자체가 없는 경우에만 호환되는 과거 기간을 사용합니다. 이전 공시의 금액과 현재 비교열이 다르면 기존값·출처·재작성 차이를 보존합니다. 중간 BS의 비교열은 전년 말이며 전년 동분기로 취급하지 않습니다.

## 계산 계약

```python
analysis = analyze(dataset)
# metrics, comparisons, checks, observations, coverage, account_history
```

각 지표에는 값·단위·상태·산식·입력 계정·출처·보류 사유가 포함됩니다. 입력의 통화·기간·범위·귀속·계정 중복을 확인합니다. 비율의 분모가 0 또는 음수면 계산을 보류합니다. 전기 금액이 0 이하인 증감은 금액 차이를 제공하고 증감률을 보류합니다.

핵심 지표는 매출 성장률, 총·영업·순이익률, 유동비율, 부채비율, 이자보상배율, CFO/순이익, 공시 차입금−현금, CAPEX·FCF, ROE·ROA, DSO·DIO, 발생액 지표입니다. 연결 ROE는 지배주주 순이익/평균 지배주주지분을 사용합니다. 평균 잔액은 현재 공시의 재작성된 기초 비교금액을 우선합니다. 중간 ROE·ROA를 연율화하지 않습니다.

현금 CAPEX는 유형·무형 현금 취득액을 구분합니다. 하나만 확보되면 완전 FCF를 만들지 않고 별도 참고값을 표시합니다. DSO는 총매출 기반 근사치입니다. 리스가 차입금에 포함됐는지 확인하지 않고 가산하지 않습니다.

| 대조 | 산식 |
| --- | --- |
| 재무상태표 | 자산 = 부채 + 자본 |
| 매출총이익 | 매출 − 원가 = 총이익 |
| 현금 연결 | 기초 현금 + CFO + CFI + CFF + 환율효과 + 기타 조정 = 기말 현금 |
| 자본 연결 | 기초 자본 + 전체 순이익 + OCI − 자본 인식 배당 + 기타 자본 변동 = 기말 자본 |

상태는 `pass`, `fail`, `incomplete`, `not_comparable`로 구분합니다. 원천 표시 단위의 반올림 오차 범위를 적용합니다. 누락된 조정액을 차액으로 생성하지 않습니다. 대조 일치는 해당 식의 확보된 항목에 한정됩니다.

## 원문·설명·보고서

원문 ZIP/XML은 크기·압축 경로·XML 외부 참조 등을 검사하고 회계정책·차입금/유동성·우발채무/약정·특수관계자·감사의견 관련 문단을 탐색합니다. 제한적으로 일반 텍스트의 앰퍼샌드와 실공시에서 확인한 표 셀·문단 제목을 이스케이프하고, 동일한 엄격 파서로 다시 읽습니다. DTD, 엔티티, 외부 참조, 허용되지 않은 경로, 일반적인 손상 태그는 계속 거부합니다. 발췌 결과는 관련 본문이며 감사의견 판정이 아닙니다. 실패 시 원인과 원문 경로를 남깁니다.

기본 설명은 계산된 지표와 비교를 이용한 규칙 기반 문장입니다. 연간과 누적을 분리하고, 전체 기간과 최신 기간의 미완료 건수를 구분합니다. 비교 가능한 영업이익·전체 순이익·지배주주 순이익의 양수↔음수 전환을 별도 표시합니다. 반복되는 관찰은 기간과 공시 출처를 표시해 묶습니다. 매출 성장률 이상치와 급격한 변동에서 동일한 경고는 중복 표시하지 않습니다. 화면 하단의 공시번호는 선택한 상세 기간에 해당합니다.

AI 메모 형식은 `COMMENTARY_FORMAT_VERSION = 7`입니다. 사용자 버튼으로 로컬 Ollama의 `/api/chat`을 호출합니다. 모델은 최신 기간의 지표·주석 근거 ID와 업종 관점 ID를 선택합니다. 사업부문·수익구조와 원가·운전자본 문단을 추가 발췌하고 업종 메모의 관련 사업 공시에 연결합니다. 금속과 식음료를 포함한 업종별 배경은 `industry_review.py`에서 관리하며, 세부 관점이 없는 업종은 일반 관점을 사용합니다. 숫자와 출처, 업종 배경, 추가 확인 질문을 화면에서 구분합니다. 구버전 메모는 다시 생성해야 합니다.

Excel·HTML·Markdown은 처리 현황, 지표·산식·제한, 표준/전체 계정 비교, 대조 입력 상세, 주석·출처를 포함합니다. Excel 원천 금액은 정밀도 손실 없이 문자열로 보존합니다. JSON은 재분석용 자료와 계산 결과를 각각 제공합니다.

## 검증과 후속 범위

현대차, 제주반도체, LG에너지솔루션의 실공시에서 원본 XBRL 통합 경로와 주석 발췌를 확인했습니다. 현대차 당기·전년 동기 기준값 4개가 일치했습니다. 주요 사례와 공시번호는 인수인계 문서를 참조하세요. 기존 `VERIFICATION.md`는 이전 시점의 기록입니다.

## 원본 XBRL 파서와 앱 통합

`dart_analyst/xbrl.py`의 `read_xbrl_archive(bytes)`는 ZIP을 메모리에서 읽고 단일 `.xbrl` 인스턴스의 수치 사실과 문맥을 반환합니다. ZIP 30 MiB, 멤버 100개, 멤버별 20 MiB, 전체 압축 해제 60 MiB, XML 요소 30만 개와 깊이 128을 상한으로 둡니다. DTD·엔티티·외부 참조를 차단합니다. ZIP 안의 XSD와 한글 라벨 링크베이스만 추가로 읽으며 외부 스키마를 내려받지 않습니다. 회사 식별자와 스킴, 실제 기간, 축과 구성원, 단위, 원금액 및 정밀도를 보존합니다. 연결 여부는 네임스페이스를 해석한 명시적 축과 구성원에서 확인합니다. 일반 연결 전체 값을 선택할 때는 추가 축과 `has_other_content`를 함께 검사해야 합니다. 텍스트·nil·복합 단위는 파서의 수치 처리 범위 밖입니다.

12월 결산이 확인된 기업의 모든 선택 기간에 `DartClient._apply_xbrl()`을 적용합니다. `_SPECS`의 표준 개념을 공통으로 사용하고 회사 식별자, 명시적 연결·별도 차원, 추가 차원 유무, 통화, 실제 기간을 검증합니다. BS 비교기는 전기 말일, 흐름은 전년 동일 기간으로 구분합니다. 자본변동표의 구성원별 합산은 별도 범위입니다. 동일 개념의 IS·CIS 반복은 당기·비교기 금액, 통화, 단위와 구성원이 같은 경우에만 통합하며 원본 행을 보존합니다.

원본 XBRL의 반올림 구간으로 동일 공시 API 값을 교차 검증합니다. 더 정밀한 API 값을 사용하는 경우 `source_field=xbrl_verified_api`와 양쪽 값을 기록합니다. 숫자의 배율과 반올림 정밀도는 구분하며 대조 허용오차에도 정밀도를 반영합니다. XBRL로 당기·비교기 값이 확인된 CF 원천 행은 전체계정 비교에서도 해당 근거를 사용합니다.

전체계정 API가 비어 있거나 최종 접수번호와 다르면 해당 행을 제외한 뒤 선택한 공시의 XBRL로 복구를 시도합니다. 복구 기간에는 확인된 원본 계정만 저장합니다. 원본 파일이 없는 경우에는 공시 번호와 실패 사유를 표시하고 기간을 보류합니다. 보통 수집에서 XBRL 자체가 실패하면 기존 전체계정 결과와 실패 안내를 유지합니다.

수치 사실의 원천 정보는 `Fact.source_details`에 기록합니다. API, 보고서 코드, ZIP 멤버명, QName, 문맥 ID, 차원, 단위, 원금액, 정밀도와 비교에 사용한 전체계정 값을 화면과 내보내기에서 확인할 수 있습니다. 접수번호는 기존 `source_id`를 사용하고 배율은 1입니다. 기존 JSON 자료의 원천 상세는 기본값으로 읽습니다.

`document.xml`은 마크업과 본문을 분리해 텍스트 블록 안의 짧은 꺾쇠 문구를 공통 정규화하고 엄격한 XML 파싱을 다시 적용합니다. 주석·CDATA·처리 지시문을 보존하고 DTD·엔티티 차단을 유지합니다. 일부 DART 표의 ENG 속성 이중 따옴표 형식도 제한적으로 처리합니다. 보정 여부는 각 발췌에 기록합니다. 기본 5개 주제와 사업부문·원가 2개 주제를 제공합니다.

정정공시 버전 저장소, 사용자 승인 매핑, 상세 roll-forward, 산업별 분석, 주석 표 전체 대조와 동종기업 비교는 별도의 후속 범위입니다.

## 2026-11-07 추가: 현금·자본 대조와 확장 계정

현금흐름표의 기말 현금(`cash_end`)을 우선 사용합니다. `cash_change` 또는 `cash_change_before_fx`와 CFO·CFI·CFF·환율효과를 독립적으로 대조해 실제 순증감의 환율 포함 범위를 확인합니다. NAVER처럼 BeforeEffect 태그의 실제 표시가 환율 포함인 경우도 있으므로 태그 이름만으로 환율을 재가산하지 않습니다. 구성 합계의 일치 근거가 확보된 경우에만 상세 현금 연결을 수행하며, 누락된 `other_cash_effects` 사실을 0으로 생성하지 않습니다.

매각예정 분류의 현금 대체(`cash_disposal_transfer`)와 처분집단 현금 순증감(`cash_disposal_change`)은 별도 사실입니다. 원문에 명시된 금액만 산식에 포함합니다. 차액을 보고 조정액을 역산하지 않습니다. 현금 워터폴도 실제 사용한 입력만 표시합니다.

확장 계정은 ZIP XSD의 실제 요소 ID→이름→확장 QName과 한글 표준 라벨을 연결합니다. 회사별 namespace, 승인된 단일 정확 라벨, 회사·통화·기간·연결 범위를 모두 확인합니다. 현재 승인 범위는 소유주 거래 합계와 위 두 현금 분류입니다. 중복·모호한 라벨이나 손상된 부가 문서는 확장 매핑을 보류하며 표준 수치 파싱은 유지합니다. 출처는 `concept_labels`, `label_sources`에 보존합니다.

라벨 파일은 최신 `*_lab-ko.xml`과 구형 `labels/lab_<식별자>-ko_YYYY-MM-DD.xml`을 지원합니다. 분류체계의 날짜가 보고기간과 다를 수 있으므로 파일명의 날짜로 재무기간을 추정하지 않습니다. 구형 대한항공 2021·2022 공시에서 이 형식을 확인하고 현금 대체를 연결했습니다.

자본의 상세 구성 대조가 미완료이고 명시적 소유주 거래 합계가 있으면 `기초 자본 + 총포괄손익 + 소유주 거래 합계 = 기말 자본`을 별도 기준으로 검증합니다(`basis=reported_equity_totals`). 상세 배당·기타 변동의 확보 여부와 합계 대조 일치는 서로 다른 결과입니다. `순이익 + OCI = 총포괄손익`도 추가로 검사합니다.

이미 명시적으로 합산한 유동·비유동 차입/리스는 각각의 정확한 XBRL 구성 개념과 교차 검증합니다. 별도의 주석 총계와 반올림이 다르다는 이유로 정확한 구성합을 폐기하지 않으며 구성항목 출처를 남깁니다.

최종 공시와 API 접수번호 불일치로 복구하지 못한 기간은 `metadata.filing_gaps`에 저장하고 화면에서 양쪽 공시 링크와 실패 사유를 표시합니다. 계산 링크베이스의 일반 합산 관계, 모든 회사 확장 계정의 자동 해석, SCE 전체 차원 roll-forward는 아직 지원하지 않습니다.

## 최근 경제 뉴스

제출본 보완(2026-11-07): AI 결과에 Dataset SHA-256 식별값을 기록합니다. 내보내기는 자료 식별값·메모 버전·기간이 일치할 때만 AI 섹션을 생성하며 문장별 지표·주석 근거를 포함합니다. 회사 전환이나 자료 변경 후 과거 메모를 섞지 않습니다. Windows 런처에는 검증용 `-NoBrowser -Port <번호>`를 추가했고 의존성 버전 범위도 확인합니다. document.xml 개별 문서 한도는 실제 기업은행 원문 21,282,590바이트를 처리하도록 30 MiB로 확장했으며 전체 60 MiB·XML 30만 노드·텍스트 800만자·DTD/엔티티 차단 한도는 유지합니다. XBRL 파서의 20 MiB 멤버 한도는 별도입니다.

`dart_analyst/news.py`가 연합인포맥스 공식 IB/기업, 정책/금융, 채권/외환 RSS를 조회합니다. HTTPS 고정 주소에서 크기와 XML 구조를 검사하며, DTD·엔티티·외부 참조를 차단합니다. 발행일은 표준 RSS 날짜 및 해당 사이트의 한국시간 형식을 처리하고 최근 7일로 제한합니다. 링크는 제공사의 기사 URL을 검증하고 중복은 기사 번호로 제거합니다. 피드별 오류는 개별 표시합니다.

뉴스는 버튼으로 불러오며 5분간 캐시합니다. 회사명과 업종 키워드, 거시경제 키워드로 최대 12건을 후보로 고릅니다. 첫 화면은 최대 5건이며, 선택 버튼으로 로컬 Ollama에 후보 기사 제목과 RSS 요약 문장을 보냅니다. 모델의 기사 ID·문장 번호를 검증해 3~5건을 표시합니다. 화면에는 원문 링크, 발행 시각, 수집 시각과 관련성 구분을 제공합니다. RSS 요약이 짧거나 없는 기사는 제목을 사용합니다. 각 피드가 제공하는 최근 목록 안에서 수집하므로 7일 전체 기사의 완전한 검색은 지원 범위 밖입니다.
